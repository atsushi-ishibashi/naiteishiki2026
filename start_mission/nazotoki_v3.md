# Start Mission 創業の記憶から最初のオフィスを探す

内定者全員で解く、創業期をテーマにした導入の謎。10人に1枚ずつ配る「創業の記録」の問いを、Slackチャネルに貼られた3本のnoteで調べる。**答えの文字はすべて伏せ、カタカナで書き込むマスだけを用意する。** 記号が付いたマスに入る1文字を持ち寄ると、最初の独立オフィスの住所が読める。カードごとの参照先は示さず、記事のタイトルと問いの内容から探してもらう。

**番地は「1」と「7」も伏せる。** 記録05の年数と、記録02の引っ越し時の気温から埋める。「9」は残し、カードは10枚のままにする。

住所をGoogle Mapsで調べ、建物名 **「東洋Mビル」** を入力するとクリア。レスポンスで、事前に決めたチーム分けと次のSlackチャネルを返す。チーム分け自体は謎にしない。

## 1. 企画の狙い

チーム別のfirst_missionは事業を知るパート。このstart_missionでは、**会社がどんな仲間と、どんな環境から始まったか**を知る。

一般的な小謎に会社名だけを付けるのではなく、創業メンバーを選ぶ基準、仕事をしていた場所、最初のオフィス、創業時からの思いなどを、各カードの答えを決める手がかりにする。

| 項目 | 設計 |
|---|---|
| 人数 | 内定者10人全員。ここではチームに分けない |
| 難易度 | 易しめ。最初に全員が手を動かし、発言しやすい導入 |
| 想定時間 | チャネル入室後8〜12分。noteを探す時間も含めて試遊で調整 |
| 中心の仕掛け | noteで創業の記録を調べ、10種類の記号とカタカナの対応を復元。番地の空欄2か所もエピソードの数字で埋める |
| 得られる住所 | 東京都千代田区九段北1-9-7 |
| 最後の問い | 最初のオフィスはどこ？ |
| 入力する答え | 東洋Mビル |
| クリア後 | チームA・B・Cのメンバーと、それぞれの次のチャネルを表示 |

この問いの「最初」は、自宅や他社の会議室ではなく、**初めて自分たちで借りた独立オフィス**を指す。導入文でもこの範囲を伝える。

## 2. オープニングからの接続

`start_mission_overview.md`にある流れをそのまま使う。

```text
オープニングムービー
 → 「Finatextと常に一緒だった備品の元へ行け」
 → 現オフィスにある、創業期からのソファを見つける
 → ソファの端の付箋から、最初のSlackチャネルへ入る
 → チャネルの3本のnoteを調べ、全員で創業の記録を復元する
```

付箋には最初のチャネル名だけを書く。ソファの裏や内部を探す追加の仕掛けは入れない。

チャネルに全員が入ったら、運営が創業の記録カードを1人1枚配る。カードはランダムに配ってよく、後のチーム分けとは結び付けない。

### 最初のメッセージ案

> 最初のオフィスはどこ？
>
> このソファは、Finatextの始まりを知っている。
> 当時の会社は、今のようなオフィスを持っていなかった。
>
> 探しているのは、自宅でも、間借りの会議室でもない。
> 初めて自分たちで借りたオフィスだ。
>
> 創業の記録と、その場所を示す宛先が残っている。
> ただ、記録の答えは抜け落ち、宛先の文字は記号に変わってしまった。
> 番地にも、数字が抜けた場所がある。
> このチャネルにある3本のnoteを手がかりに、記録を復元してほしい。
> みんなの記録を合わせたら、宛先にある建物の名前を報告しよう。

### チャネルに置くnote

次の3本を、記事タイトル付きのリンクでひとまとめにして置く。カード番号との対応表、記事内の見出し、検索用のキーワードは添えない。

- [Finatextの10年を振り返ってみる](https://note.com/ryotafinatext/n/n3b869fccd918)
- [Finatextを創業してから上場するまでの10の学び](https://note.com/ryotafinatext/n/n65ab81d5f084)
- [Finatextがビジョン/ミッションからカルチャーをアップデートするまでの全容](https://note.com/110_110_110/n/n76729c01a16f)

案内は「カードの答えは、この3本のnoteの中にあります。分かったことは自由に共有してください」で十分。全員が3本を最初から最後まで読む必要はなく、自分の問いに関係しそうな記事を探す。

ゲーム中の記録カードと宛先は、実話をもとに作る架空の資料。実在した引越し伝票や、林さんの文章そのものとしては扱わない。

## 3. 参加者に渡すもの

- **創業の記録カード10枚**：1人1枚。各カードに短い問いと、答えの文字数分の解答マス。1マスだけに記号を付ける。記録02・05には数字を書く欄も付ける。答えの文字・数字や参照先のヒントは載せない。
- **宛先の台紙1枚**：全員で見えるA3程度。暗号化された住所、番地の数字を入れる空欄2か所、記号の対応を書く欄。
- **筆記具10本**：各自がカードに書き込めるようにする。
- **Slackに置く3本のnoteリンク**：参加者は自分のスマートフォンなどで開く。
- **Slackの解答フォーム**：入力欄は「建物名」の1つだけ。

専用Webアプリは不要。紙とSlackの回答窓口で進行できる。台紙を大きな画面にも表示すると、10人で共有しやすい。

### 全員に伝えるルール

> noteで見つけた答えをカタカナにして、左から1マスに1文字ずつ書いてください。
> 記号が付いたマスに入る文字を、宛先の同じ記号に当てはめます。
> 「□」は普通の空欄です。マスごとに違う文字が入って構いません。
> 小さい「ャ・ュ・ョ・ッ」と長音「ー」も1マス使います。「ガ」「パ」などは点や丸も含めて1マスです。
> カタカナの解答欄では、年数は「○年」、人数は「○人」まで含めて書いてください。
> 数字の欄があるカードは、そこには数字のまま書いてください。
> 記録も、分かったことも、自由に見せ合って構いません。

既に創業の話を知っている必要はない。カードの問いに合う答えをnoteで見つけ、読みを解答マスに書く。記事内検索や、同じ記事を読んでいる人との情報交換も自由。答えを見つけて記号のマスの1文字を共有する。数字欄のある2枚は、その数字も共有する。番地へ使う桁は台紙で明示する。

## 4. 創業の記録カード10枚

下表では、普通の空欄を「□」、印付きの空欄を「★」などで表す。印刷時はすべてを同じ大きさのマスにし、記号は該当マスの上に小さく添える。記号のあるマスにも答えを書き込めるようにする。

### 1枚の見せ方

記録01なら、例えば次のようにする。

```text
創業の記録 01　仲間選び

創業メンバーを選ぶとき、
スキルだけでなく何を重視した？

                ★
        ［　］［　］［　］［　］

★ が表す文字：［　］
```

★は2マス目の真上に置く。noteで問いの答えを確かめて「ヒトガラ」と書くと、そのマスには「ト」が入る。自分のカードで分かった対応を、全員の台紙へ書き足す。

この段階では1人の問題を難しくしすぎない。各自が1つの創業エピソードを理解して持ち寄れることを優先する。

## 5. 全員で宛先を復元する

台紙には、次の文字列を大きく印刷する。

```text
最初の独立オフィスへの宛先

★◆▲●◆★　■♥♣☀　☀♣☂▲♪　［年数］-9-［気温の一の位］
```

「年数」「気温の一の位」は、空欄の上に添える小さなラベル。数字を書くスペースを確保する。台紙には次の案内も置く。

> 番地の空欄には、カードに記録した数字を使ってください。
> 「年数」はそのまま、「気温」は一の位だけを入れてください。

その下に、記号の対応を記入する欄を用意する。欄の順は記録番号と無関係でよい。読む対象は住所の文字列であり、カードを並べ直す必要はない。

```text
▲＝［　］　☂＝［　］　♥＝［　］　★＝［　］　♪＝［　］
☀＝［　］　●＝［　］　■＝［　］　◆＝［　］　♣＝［　］
```

10枚の記録から文字の対応がそろい、記録05の「1年」と記録02の「37℃」を共有すると、番地の空欄には「1」と「7」が入る。

完成した宛先は、

```text
トウキョウト　チヨダク　クダンキタ　1-9-7
```

と読める。漢字にすれば、**東京都千代田区九段北1-9-7**。

数字のうち「9」と区切りのハイフンは、破損せず残っている設定。隠した「1」と「7」はエピソードの数字からそのまま拾えるようにする。気温から使う桁も明示し、計算や桁の選び方を当てる追加の謎にはしない。これらの数字で住所が決まったという史実ではなく、実話を手がかりに宛先を復元するゲーム上の対応付け。

### 10人で解くための進め方

1. 最初に1人1枚を受け取り、チャネルの3本のnoteから自分の問いに関係する記述を探す。
2. 見つけた答えをカタカナで解答マスに書き、エピソードと対応文字を短く共有する。「創業メンバーは6人だからロクニン。☀のマスにはクが入る」のように伝える。記録02・05の人は数字も共有する。同じ記事にほかの人の答えがあれば、声を掛けてもよい。
3. 台紙へ対応を書き込み、手の空いた人が住所の復元を進める。番地には年数と気温の一の位を入れる。
4. 全員で住所を読み、建物を地図で確認する。

全10種類の記号が住所に実際に現れるため、使用されないカードはない。答えの文字をすべて伏せることで、単語の残りだけから記号を埋める解き方を防ぐ。ただし、問いから答えを予想したり、住所の一部から残りを推測したりすることは可能。予想できた人にもnoteで内容を確かめてもらう。10人分の個別認証や、noteを読んだ証拠を入力させる仕組みは設けない。早く住所が見えた場合も、未共有の記録の内容を短く確認してから解答へ進む。

「資料を見せてはいけない」「一人ずつしか話せない」といった制限は付けない。最初に小さな成功を持ち寄れる、話しやすい場にする。

## 6. 地図で建物名を確認する

台紙の下には、次の案内を置く。

> 宛先が読めたら、Google Mapsでその住所を調べよ。
> 報告するのは、そこにある建物の名前。

「Google Mapsを開く」リンクは、検索語の入っていない地図トップを使う。あらかじめ住所を埋め込んだリンクを置くと、復元前に宛先が分かってしまう。

正解は **東洋Mビル**。住所と建物名の対応は、[建物情報](https://www.chintai-jimusho.com/building/786/)でも確認できる。階数や現在の入居企業名は答えに含めない。

本番前に、参加者が使う端末で住所検索から建物名へ進めるか確認する。Google Maps上で名称を見つけにくい場合は、同じ住所で建物情報を検索してよい。検索操作の難しさで時間を使わせない。

## 7. 回答とチーム分けのレスポンス

回答フォームは、**建物名の1欄だけ**。

- 正解：`東洋Mビル`
- 全角・半角のM、英字の大小、前後や途中の空白は正規化する。
- `東洋Ｍビル`、`東洋 M ビル`、`東洋mビル`も正解にする。
- 住所を入力した場合は「建物名を入力してください」と返す。
- それ以外は「宛先の住所にある建物名を、もう一度確認してください」と返す。

正解時は、事前の名簿に基づくチーム分けと、次のチャネルを固定のメッセージで返す。カードの記号、解答順、担当したエピソードはチーム分けに使わない。

### レスポンス文案

> 正解。最初の独立オフィスは、東洋Mビル。
>
> ここから、会社の歴史は3つの道へ続いていく。
> 次は、以下のチームで各チャネルへ進んでください。
>
> **Team A　保険**
> メンバー：{{TEAM_A_NAMES}}
> 移動先：{{TEAM_A_CHANNEL}}
>
> **Team B　証券・AI**
> メンバー：{{TEAM_B_NAMES}}
> 移動先：{{TEAM_B_CHANNEL}}
>
> **Team C　データ**
> メンバー：{{TEAM_C_NAMES}}
> 移動先：{{TEAM_C_CHANNEL}}

`{{...}}`は運営が本番の氏名・実在するチャネルへのリンクに差し替える欄。既存の編成ではAが3人、Bが4人、Cが3人。ここに追加の解錠や暗号は入れない。

## 8. 後の謎との違い

| ミッション | 既存の中心的な仕掛け | startで避けること |
|---|---|---|
| A first | 条件でカードを配置し、台紙・封筒で読み直す | 配置条件、裏面、封筒、同じ文字盤の再読を使わない |
| B first | 沿革順の迷路と共通経路 | 時系列の並べ替え、迷路、経路の重ね合わせを使わない |
| C first | グラフ接続、原点の置き直し、文字の消去 | グラフ、座標変更、残った文字を読む仕掛けを使わない |
| A second | 当事者になって自分の番号を推理 | 視点変更や、他人の知識についての推理は使わない |
| B second | 工程の削除・再接続と工数制約 | 費用削減のパズルにはしない。引越し費用の話は創業の記録として扱う |
| C second | 分断された観測・操作・仕様から装置を診断 | 固定役割や試行による状態変化を使わない |
| Final | 会話から案件更新、時計への変換、円の向き | Slackの長い会話ログ、表の更新、時計、回転を使わない |

startでは **記号と文字の一対一の対応を復元する**。使うマスは各カードに最初から明示し、配置や別の謎から文字の取り出し位置を推理させる工程は入れない。人物の考え方や行動をPrincipleの名前に結び付ける回収は、second以降に残す。

## 9. ヒントと時間配分

| 詰まったところ | ヒント |
|---|---|
| カードで何をするか分からない | noteで問いの答えを探し、カタカナでマスに書いてください。記号が付いたマスには何が入りましたか |
| 「□」にも同じ文字を入れようとする | 「□」は空欄です。それぞれのマスに、答えの文字を順に書いてください |
| 言葉は見つかったがマスに収まらない | 年数は「○年」、人数は「○人」まで含め、小さい文字も1マスで数えてください |
| 自分のカードは読めたが、その先が分からない | 宛先にも、同じ記号が使われています |
| 分からない記号が残る | その記号が入った記録を、誰かが持っていませんか |
| トウキヨウトと読んでしまう | 「ビジョン」の「ョ」は、小さい文字です |
| 番地の空欄が埋まらない | カードに、年数や気温を数字で書く欄はありませんか |
| 気温をそのまま番地に入れてしまう | 台紙に書かれている通り、気温は一の位だけを使います |
| 住所が読めたが止まる | 最後の問いは、住所ではなく建物の名前を聞いています |

上のヒントは運営が詰まったときに使うもの。カード別の参照記事や該当箇所を示すヒントは、事前には配らない。

目安は、配布と導入2分、noteの確認・復元・共有4〜5分、番地を含む住所の復元と地図の確認1〜3分、回答と移動案内1〜2分。目標は全体で8〜12分だが、数字欄も含めた記事探しの時間は初見の試遊で確かめる。短く終わっても、導入としては問題ない。後のミッションに難しさを残す。

## 10. 制作と試遊の確認事項

- [x] 10枚すべてで、答えのカタカナの文字数とマス数が一致し、記号のマスから意図した1文字が取れる。
- [x] 各カードが示す記号は1種類で、対応文字は全10種類で異なる。
- [x] 住所の暗号を置換し、年数と気温の一の位を入れると「トウキョウト チヨダク クダンキタ 1-9-7」になる。
- [x] 住所に全10種類の記号が現れ、未使用のカードがない。
- [x] 10枚の答えを3本のnote本文で確認できる。資料1から5問、資料2から3問、資料3から2問。
- [x] 数字欄の答え「1年」「37℃」を資料1で確認できる。1と37の一の位を使うと番地の空欄が1と7になる。
- [ ] チャネルに3本のnoteがタイトル付きで並び、参加者の端末から開ける。
- [ ] 参加者用カードに記事名・著者名・URL・節番号が紛れ込んでいない。
- [ ] 解答マスに答えの一部が印刷されておらず、記号がどのマスに付いているか明確に分かる。
- [ ] 番地の「1」「7」が参加者用の台紙に印刷されておらず、「年数」「気温の一の位」のラベルが見やすい。
- [ ] 参照先のヒントなしで、noteの確認・復元・共有が目安の時間に収まる。
- [ ] 印刷した記号が見分けられる。特にスートや太陽は絵文字ではなく単色の図形にそろえる。
- [ ] 小さい「ョ」と大きい「ヨ」が、台紙でも読み分けられる。
- [ ] 10人から台紙が見え、少数の参加者だけで作業が進まない。
- [ ] 住所検索で東洋Mビルを確認できる。表示が変わった場合の補助資料も用意する。
- [ ] 正解レスポンスに、全員の名前と正しい次のチャネルが入っている。
- [ ] ソファの付箋・最初のチャネル・カード配布のタイミングがつながっている。

先頭4項目は文字列と数字の対応を計算して確認済み。5・6項目目はnote本文と照合済み。印刷物、Slackフォーム、当日の検索導線と所要時間は制作・試遊で確認する。
