# Team B Second Mission 12ポイントで回答を届ける

4人でカードを使い、架空の証券サービスの問い合わせ対応を組み立てる、10〜15分想定の謎。現在の工程は30pt。現在の順序のまま1対1でAI・システムに置き換えても16.2ptまでしか下がらない。**転記と社内報告を工程から外し、必要な自動処理をまとめると、品質と人間判断を保ったまま12ptになる。**

取り戻す鍵は **KEY 02 AI+**。正解は、後述する5枚のカードを所定の順に接続した構成。Principleの名前を答えさせるのではなく、正しい構成を実行すると鍵が現れる。

以下は制作・運営用の企画案。参加者向けの文面・カード・ルールを抜き出して使う。問い合わせ、帳票、工数はゲーム用の架空設定であり、実在業務の推奨手順や実測値ではない。

## 1. 既存ミッションとの違い

| 既存の仕掛け | 今回の設計 |
|---|---|
| A first：条件に従う9枚配置、裏面や封筒から文字抽出 | 作るのは実行できる業務フロー。カードの裏や配置の文字は読まない |
| B first：沿革順、4つの迷路、共通経路 | 迷路・沿革・重なり・日付検索を使わない |
| C first：グラフ接続、原点変更、接続部の文字を消す | 不要な工程を外すのは仕事の再設計のため。削除した跡や残った文字に暗号を置かない |
| Final：Slack記録をシートに反映し、時刻を変換 | 過去ログの転記・表の更新をさせない。試験用の入力に対してフローを実行する |

30ptからの削減は目的ではなく制約。**目的は、根拠のある回答を必要な判断を経て届けること**とする。

## 2. 導入と参加者に渡す目的

Slackの案内文：

> 「AIがそう言ってるなら、いいんじゃないですか。」
>
> 未来の窓口には、AIの下書きだけが積み上がっている。
> 必要なのは、もっと速く下書きを増やすことだろうか。
> 今回の依頼を、条件を満たす形で完了させてほしい。

ミッションカード：

> 利用者から届いた問い合わせに、根拠を添えた回答を届けよ。
> 1件に使える工数は **12pt以下**。
>
> ・回答には、依頼内容と、根拠資料の出典IDが必要。
> ・原票の不足や食い違いは、人間が判断できる形で残すこと。
> ・人間が確認して許可するまで、回答を外部へ送らないこと。
> ・根拠が不足している案件、食い違う案件、重要判断を含む案件は、送信せず人間の対応待ちにすること。

画面には、参考として **CURRENT FLOW** が既に並んでいる。見出しは「現在使われている構成」。これを正規の工程数・必須の型だとは書かない。

## 3. 現在のフローとカード

### 最初に並んでいる7枚

```text
H1 原票を集める 5pt
 → H2 転記表を作る 4pt
 → H3 根拠を照合する 6pt
 → H4 社内報告書を作る 3pt
 → H5 回答案を作る 6pt
 → H6 人間が送信可否を判断する 4pt
 → H7 人手で送信する 2pt

合計30pt
```

### 13枚のカードの全データ

同じ機能の人間版と自動版は同時に使えない。H6には自動版を用意しない。表のIDは小さく印刷し、題名・入力・出力・工数を大きくする。

| ID | 種別・工程 | pt | 入力 | 出力・働き |
|---|---|---:|---|---|
| H1 | 人間：原票を集める | 5 | 受付済みの問い合わせ | 原票束。依頼内容と出典IDを保持 |
| S1 | システム：原票を直接取得 | 2 | 受付済みの問い合わせ | H1と同じ原票束。構造化済みで取得できる |
| H2 | 人間：転記表を作る | 4 | 原票束 | 転記表。原票束も引き続き参照可能 |
| S2 | システム：転記表を作る | 3 | 原票束 | H2と同じ転記表。原票束も保持 |
| H3 | 人間：根拠を照合する | 6 | 原票束 | 検証束。出典IDと「通常／要人間対応」の区分 |
| A3 | AI：根拠を照合する | 4 | 原票束 | H3と同じ検証束。原票不足・矛盾・重要判断を要人間対応にする |
| H4 | 人間：社内報告書を作る | 3 | 検証束 | 社内報告書。検証束も保持 |
| A4 | AI：社内報告書を作る | 3 | 検証束 | H4と同じ社内報告書。検証束も保持 |
| H5 | 人間：回答案を作る | 6 | 検証束 | 通常なら根拠付き回答案。要人間対応なら論点メモ |
| A5 | AI：回答案を作る | 4 | 検証束 | H5と同じ回答案または論点メモ。資料にない情報を補わない |
| H6 | 人間：送信可否を判断する | 4 | 検証束＋回答案または論点メモ | 通常なら送信許可。要人間対応なら保留・担当者への引き継ぎ記録 |
| H7 | 人間：送信する | 2 | H6の判断結果 | 許可時のみ根拠付き回答を送信。保留時は送信しない |
| S7 | システム：許可分を送信する | 1 | H6の判断結果 | H7と同じ。送信記録または保留記録 |

全カードは、記載された入出力と機能だけを持つ。「AIならついでに送信もできる」などの追加解釈はしない。

H3/A3の入力は **原票束** であり、転記表ではない。H5/A5の入力は **検証束** であり、社内報告書ではない。**なくても成果に影響しない工程が、現在の運用には残っている**ことを、この入出力で発見させる。

人間のH3やH5を残すと、途中の確認がH6を兼ねるようにはしない。H6は外部送信の可否を判断する別の責任を持つ。

## 4. フローと工数のルール

参加者向けの基本ルール：

> 使用するカードを、実行順に矢印でつないでください。
> 各機能は1回まで。同じ機能の人間版と自動版は、どちらか一方です。
> 入力に書かれた資料がそろっていない工程は実行できません。
> 作った資料は、その後の工程でも使えます。
>
> **AI・システムが2枚以上続く区間は、その区間の合計工数が30%減ります。**
> 人間の工程を挟むと区間が切れます。自動カード1枚だけの区間は割引されません。
> 人間の工数は割引されません。工数は小数第1位まで、そのまま計算します。

工数の例は、本問と異なる小さなカードで `自動2＋自動3 → 3.5pt`、`自動2＋人間1＋自動3 → 6pt` と示す。

並列実行、分岐の配線、繰り返し実行は今回の盤面では扱わず、**1本のフローに絞る**。保留時に送らない動きはH6と送信カードの機能で表す。方向性資料のすべての操作を入れず、「工程をなくす」「自動処理を連続させる」「人間の判断を残す」に集中する。

### 操作の見せ方

- 7枚を結ぶ初期の矢印に、固定の工程番号や7個の必須枠を置かない。
- カードはドラッグ可能。各カードの操作メニューに「構成から外す」がある。
- 外したカードはトレーに戻る。トレーから再び使える。
- 「全部の工程をAIに変えよう」「自由に組み替えよう」といった解法の指示は出さない。
- 操作可能性は隠さない。詰まる理由を、削除ボタンを見つけられないことにしない。

## 5. 想定する失敗と気づき

### 最初は、現在の7工程をすべて残して置き換える

```text
S1 2 → S2 3 → A3 4 → A4 3 → A5 4 → H6 4 → S7 1
```

最初の自動5枚は `2＋3＋4＋3＋4＝16pt`。連続処理により `16×0.7＝11.2pt`。

合計は **11.2＋4＋1＝16.2pt**。これが現在の7機能・順序を残す場合の最小工数で、12ptには届かない。

7機能を残して順序まで変えると最小15.9ptにはなるが、それでも不達。例えば社内報告を人間判断の後へ移し、送信と連続させると15.9ptになる。順序変更という別の工夫を正しく認めても、不要な工程をなくす発見が必要な数値にしている。

失敗時には「品質条件：達成」「工数：16.2／12pt」と返す。AIの性能が足りないのではなく、仕事の構成を考え直す必要があると分かるようにする。

### 次に、何の成果物が本当に必要かを見る

問い合わせに答えるために、転記表や社内向けの報告書そのものは要求されていない。後続カードもそれらを入力にしていない。

> 「原票がそのまま読めるなら、転記表はいらないのでは？」
> 「回答案は検証束から作れる。社内報告書を経由する意味がない」

この2枚を外すと、S1・A3・A5が直接連続する。

## 6. 正解のフロー

```text
S1 原票を直接取得 2pt
 → A3 根拠を照合 4pt
 → A5 回答案を作る 4pt
 → H6 人間が送信可否を判断 4pt
 → S7 許可分を送信 1pt
```

工数は、

```text
自動区間： (2＋4＋4) × 0.7 ＝ 7pt
人間判断： 4pt
送信処理： 1pt（単独の自動カードなので割引なし）
合計：12pt
```

ただカードを外すだけでなく、**原票→検証束→回答案の自動処理を一続きにする**ことも必要。途中に人間工程を置くと工数が増える。

### なぜ正解が1つになるか

- 原票束、検証束、回答案または論点メモ、人間の判断、送信または保留の記録は、目的上すべて必要。
- これらの生成順序は、カードの入力依存によって固定される。
- 必須5機能を最小工数で実行できる組み合わせが `S1 → A3 → A5 → H6 → S7`。
- 必須機能のいずれかを人間版へ変えると、工数は12ptを超える。
- 転記表や社内報告書を追加する構成も12ptを超える。
- H6を削除したり、送信をH6より前に移したりすると、人間判断の条件に違反する。

目的を満たすカード選択と、入力条件を満たすすべての並び順を列挙した。成立する1,840構成のうち、12pt以下はこの1構成だけ。7機能をすべて残す場合は最小15.9pt、現在の順序も維持する場合は最小16.2ptである。正解をIDの完全一致だけで判定せず、実装でも入出力・条件・工数から判定する。

## 7. 実行テスト

外部の生成AIや実データは使わず、カードの働きを固定した小さなシミュレーターで判定する。モデルの回答のばらつきや事実誤認を、この謎の難易度に持ち込まない。

テスト条件は最初から閲覧可能にする。

| 入力例 | 原票に含まれる内容 | 期待する最終状態 |
|---|---|---|
| 通常の問い合わせ | 問い合わせと回答根拠がそろい、出典IDが一致 | 根拠付き回答が作られ、人間が許可した後に1回だけ送信 |
| 根拠不足 | 回答に必要な資料が1つ欠けている | 不足内容を残して人間へ引き継ぎ。外部送信なし |
| 原票の矛盾 | 同じ項目について2つの原票が食い違う | 両方の出典IDと論点を残して人間へ引き継ぎ。外部送信なし |
| 重要判断あり | 原票に「担当者の個別判断が必要」の区分がある | 人間の対応待ち。自動承認・外部送信なし |

H6はゲーム上、通常の案件だけ許可し、残る3ケースは保留にする。プレイヤーがクリックだけで保留を許可に変える操作は設けない。

工数は処理件数や分岐結果によらず、**提出した構成の予約工数**として全カード分を数える。保留で送信しなかったからS7を無料にする、といった別解を防ぐ。

### 返すエラー

| 構成の問題 | 表示例 |
|---|---|
| 入力資料がない | 回答案を作る工程に、検証束が届いていません |
| H6がない | 外部送信の可否を判断する人間の工程がありません |
| H6より前に送信 | 送信許可がまだありません |
| 機能を重複させた | 同じ機能は1回までです |
| 品質は満たすが高い | 品質条件：達成／工数：16.2pt／上限：12pt |

「削除すべきカードはS2とA4です」のような答えの直接表示は、通常の判定では出さない。

## 8. 4人での参加とヒント

物理カード13枚、目的カード1枚、計算メモ1枚を机に置き、Web画面には同じ構成を入力する。全員に端末は不要。紙上で組み立てた構成を1台の画面で試せる。

初回は「目的を確認する」「入出力をつなぐ」「工数を計算する」「例外ケースを確かめる」の4観点を分担できる。固定の秘密情報や専任操作権限は設けず、途中で担当を変えてよい。

| 段階 | ヒント |
|---|---|
| 1 | 今回求められている成果物と、今の工程が作っている成果物を比べてください |
| 2 | 次のカードは、直前のカードが作った資料を本当に使っていますか |
| 3 | 原票束から照合ができ、検証束から回答案が作れます。その間の資料は必要でしょうか |
| 4 | 転記表と社内報告書を外したとき、残る自動工程の工数をまとめて計算してください |

「全部AIにする」と言い始めた場合は、「人間が責任を持つ判断は、どこに残っていますか」と返す。

想定配分は、目的理解2分、1対1の置き換え3分、工程の必要性の見直し4〜6分、検証と成功画面2分。試遊で数値を変える場合は、別解と1対1置き換えの最小工数を再確認する。
